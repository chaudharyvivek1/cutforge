## 1 — Colour management and LUTs are specified and not compiled

**Severity: high, and it is the largest remaining gap.**

§11.4 specifies a working colour space, per-shot matching and a creative LUT at the end of the chain. `tests/compiler.py` implements a tone map for HDR sources and nothing else: no working-space conversion, no LUT application, no per-shot matching.

The compiler raises on an unimplemented effect rather than skipping it, so this cannot produce a wrong render silently — it produces a loud refusal. That is the right failure mode and still a gap: an IR with a `lut` effect cannot be compiled at all.

**Proposed resolution.** Implement `lut` as a `lut3d` filter with the file resolved through the manifest, and add a golden file with a small identity LUT so the chain is proved end to end. Then the working-space conversion, which is the harder half.

## 2 — The layout check skips silently without LibreOffice

**Severity: medium, and it is the failure mode the test itself warns about.**

`TestLayout` is decorated `skipUnless(shutil.which("soffice"))`, so a machine without LibreOffice reports success while running nothing. The CI job installs it, but a contributor's laptop may not, and the skip is easy to miss in a wall of dots.

**Proposed resolution.** Make the skip visible: print a line naming what was skipped and why, and have the workflow assert the layout job actually ran rather than skipped. A test that can pass by not running is a test that will.

## 3 — The golden files have no reviewer

**Severity: medium, process rather than code.**

A golden file is only as good as the review that approved it. Regenerating `golden/*.graph` after a compiler change is a one-line command, and nothing records *why* a graph changed. The v1.8 round did exactly this: the Appendix A golden moved from `offset=0` to `offset=0.000000` because the wipe work changed a format string, and the regeneration was justified in a commit message rather than in the artefact.

**Proposed resolution.** A header comment in each golden naming the version that approved it and the reason for the last change. Cheap, and it turns "the golden changed" into "the golden changed because".

## 4 — The break-even uses one rate for committed capacity

**Severity: low.**

§20.3's break-even solves for volume at a fixed commitment rate and a fixed peak. Both move: committed capacity is priced in tiers, and the peak is a property of the workload rather than a constant.

**Proposed resolution.** State the break-even as a function of peak and committed rate — `g* = 1000 + (provisioned × R_c − 90) / 0.05` — and leave the numbers as one worked point. The formula is the durable part.

## 5 — `_tonemap` assumes an SDR project and an HLG or PQ source

**Severity: low.**

The compiler tone-maps when the project is `rec709` and the source transfer is HLG or PQ. It does not handle the reverse — an SDR source on an HDR timeline, which needs an inverse map rather than none — and it does not consult the renderer manifest for a tone-map operator, so two renders of the same IR could differ if the operator changed.

**Proposed resolution.** Handle the SDR-to-HDR direction explicitly, and read the operator from the manifest rather than hardcoding `hable`, which is what §11.6 says the manifest is for.

## 6 — The compiler emits no `amix` for a multi-track audio bus

**Severity: medium, verification debt.**

`compile_ir` produces one chain per audio item and never mixes them. §11.1 says the compiler emits "a mixed, loudness-normalised audio bus"; the reference compiler emits neither the mix nor the normalisation. Appendix A has one audio track, so the golden file cannot show the gap.

**Proposed resolution.** Add an `amix` with `normalize=0` and a `loudnorm` stage, and a fixture with two audio tracks — a music bed and dialogue — so the mix is proved and the ducking rule has somewhere to live.

## How this list is maintained

A finding enters when it is noticed and substantiated — a section number, an arithmetic error, or two rules that cannot both hold. It leaves when a version resolves it, and the resolution is named in that version's §0 table. It is never quietly dropped.

Four of the six above are verification debt rather than defects: the rule is right and the code does not yet reach it. That proportion has shifted as the versions have gone on — v1.6 and v1.7 each closed defects, v1.8 closed the artefact, and what remains is the distance between a complete specification and a complete reference implementation.
