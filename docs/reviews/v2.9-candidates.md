## 1 — The reference store has eight tables the published migration does not

**Severity: high, and it is the schema-drift defect in a new form.**

`tests/store.py` now creates `tokens`, `revocations`, `buckets`, `usage`, `webhook_endpoints`, `deliveries`, `assets` and `asset_derivatives`. §13.3's migration publishes seventeen tables, of which `assets` and `asset_derivatives` are two — the other six exist only in the reference.

`build/check_sql.py` validates the published migration against itself and against the state list in the code. It does not compare the *table set* in the code against the table set in the document, so a table can be added to the reference and never reach the specification.

That is precisely the drift v1.3 named, and the checker that was supposed to prevent it covers states and not tables.

**Proposed resolution.** Extend `check_sql.py` to parse `CREATE TABLE` from `tests/store.py` and diff the names against the migration, failing on anything present in one and not the other. Then either add the six tables to §13.3 or mark them explicitly as reference-only.

## 2 — Rendering at scale: no NVENC, no chunked render, no segment publishing

**Severity: high, and it is the largest remaining gap in the engine.**

The renderer hashes two graphs at 320×180 on a CPU. §11.5's chunked render — split at cut points, publish segments content-addressed, resume from six of eight — has never run, and neither has a single NVENC encode.

**Proposed resolution.** Chunked render first, on the CPU: it needs no hardware and it is where the resume logic lives. Then the NVENC path, which needs the runner §12.9's matrix already assumes.

## 3 — Transcription is a contract with no engine behind it

**Severity: medium, and stated as such.**

`analysis.Transcript` remaps word times correctly and nothing produces one. §10.4 specifies word-level timings from an ASR model; this repository has no model and no audio analysis at all.

**Proposed resolution.** An adapter over any ASR that emits the contract, tested against a recorded transcript. The remap is already proved; what is missing is the producer.

## 4 — Three GPU signals remain unemitted

**Severity: medium, blocked.**

Unchanged since v2.6. No GPU runner, and a constant would be worse than an absence.

## 5 — VFR ingest is specified and the conform map only handles CFR

**Severity: medium, and v2.8 created it.**

`ingest.conform()` always emits an affine map. §5.9.4 specifies a table-backed map for variable-rate sources, and the fixture generator in `tests/vfr_fixture.py` can produce one — but ingest has no path that detects VFR and writes the table.

A VFR phone capture ingested today would get an affine map that is silently wrong, which is worse than an error.

**Proposed resolution.** Detect VFR from the packet timestamps during probe, and emit the table map when the spread exceeds §5.4's threshold. The fixture already exists; the plumbing does not.

## 6 — The identity corpus still has no data

**Severity: medium, unchanged for five versions.**

Procurement. `tests/corpus.py` remains the specification of what to buy.

## How this list is maintained

A finding enters when it is noticed and substantiated — a section number, an arithmetic error, or two rules that cannot both hold. It leaves when a version resolves it, and the resolution is named in that version's §0 table. It is never quietly dropped.

Finding 1 is the same defect as v2.4's, one level up: then the code gained a state and the schema did not; now the code has gained tables and the schema has not. The checker was extended to catch the first and never taught to catch the second, which is what a checker written against one instance of a pattern will always do.
