All six findings from the previous list are resolved in v2.11. What follows is what v2.11 leaves open, and the list has narrowed to two things: what needs hardware, and what needs a decision.

## 1 and 2 — the GPU findings, unchanged

**Severity: high and medium; both blocked on the same purchase.**

The code path now exists and refuses clearly, which is the most a repository can do without a device. `usable_encoder()` proves a device with a one-frame encode; the benchmark workflow is manual-only; §12's numbers remain targets. Nothing here changes until a machine exists.

## 3 — The two-pass planner has never seen a real model

**Severity: high, and it is now the only unblocked high finding.**

The seam exists and a recorded response replays through both passes. What has never happened is a model producing a plan. The plumbing is proved; the premise is not.

**Proposed resolution.** One adapter over any provider, a budget for the evaluation corpus, and the two-pass path run end to end on the §19.2 prompts. This is the next real milestone and it needs a purchase, not a version.

## 4 — The identity corpus still has no data

**Severity: medium, unchanged for eight versions.** Procurement.

## 5 — `check_against_template` measures agreement, not quality

**Severity: medium, and v2.11 created it.**

The function compares a model's plan to the deterministic planner's decisions — same shots, same order, same total. That measures *agreement*, and a model that agrees with a template is not necessarily a model that produces a good edit. The template planner is a floor, not a standard.

**Proposed resolution.** A rubric the corpus scores against — hook strength, payoff placement, pacing against the beat grid — with human labels on a small set. That is the difference between "the model reproduces the baseline" and "the model is better than the baseline", and only the second justifies the cost.

## 6 — The worker has no idle loop that calls `idle_sweep`

**Severity: low.**

`Worker.idle_sweep()` exists and nothing calls it, which is the same defect one level down from the one v2.11 fixed: a mechanism nobody runs is not a policy, and a sweep nobody schedules is not a sweep.

**Proposed resolution.** A loop — `run_forever(interval)` — that sweeps when `run_once()` returns `None`, with a test that drives it three times and asserts the sweep ran twice.

---

## 7 — The suite now exceeds a five-minute budget

**Severity: low, and v2.11 created it.**

292 tests take 283 seconds, because Appendix A generates four 3000-frame fixtures for the split-rule test. `python3 -m unittest discover` no longer fits inside a five-minute call or a comfortable CI step, and the render tests are almost all of it.

**Proposed resolution.** Split discovery in CI — fast tests first, render tests in a second job — and cache the Appendix A fixtures between runs. The fixtures are deterministic, so generating them once per checkout is waste, not coverage.

---

## How this list is maintained

A finding enters when it is noticed and substantiated — a section number, an arithmetic error, or two rules that cannot both hold. It leaves when a version resolves it, and the resolution is named in that version's §0 table. It is never quietly dropped.

The list has now narrowed to the point where a version can no longer be justified by what it closes: four of six findings are gated on a purchase, and the two that are not are small. **This is the signal that the next step is not v2.12** — it is a GPU machine, a model budget and a corpus. The roadmap says the same thing in numbers.
