## The list is now five items and four of them are purchases

For eight consecutive versions this list has opened with the same four entries. v2.17 closed the last item that a version could close, and `PADDING-AUDIT.md` puts a number on the consequence: the last seven versions each added between four and eleven net lines to a 2,770-line specification, and four of them were the same activity at larger scale.

**A v2.18 would close nothing.** There is no finding left that a session in this repository can resolve:

- Findings 1 and 2 need a device.
- Finding 3 needs a budget.
- Finding 4 needs a contract and weeks of lead time.
- Finding 5 needs a person who is not the author of the rubric.

The only honest output of a v2.18 would be another review of the same five items, which the padding audit would then correctly classify as padding.

## What to do instead

| Action | Cost | Closes |
|---|---|---|
| Rent one GPU hour | ~₹500–2,000 | Findings 1 and 2, and fills §12's matrix |
| Set a model budget | Decision + spend | Finding 3, and the first model-made plan |

| Ask one other person for twenty labels | An afternoon of their time | Finding 5 |

Any one of these is worth more than the next version, and the first two are the difference between a specification and a product.

## If a version must be cut anyway

The only defensible content would be **deletion**: the specification is 2,770 lines for a system whose reference implementation is ~5,000 lines of Python, and the ratio has never been examined. A v2.18 that removed sections the implementation has proved unnecessary would be real work — and it would be the first version since v2.3 whose main change was a deletion.

That is worth doing eventually. It is not worth doing before a GPU has run the matrix, because deleting a section the hardware has not yet exercised is guessing.
