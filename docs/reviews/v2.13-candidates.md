## 1, 2, 3 and 4 — the four purchases

**Severity: high, medium, high, medium. All blocked outside the repository.**

A GPU machine closes the capacity model and three signals. A model budget closes the last unproven premise. A corpus closes identity accuracy. No version can substitute for any of them, and three consecutive versions have now said so — which is itself the finding: the specification has outrun what this environment can prove.

## 5 — The rubric's thresholds are asserted, not calibrated

**Severity: medium, and v2.12 created it.**

The hook band is 0.7–3.2 s, the pacing target is one cut per six seconds, and the payoff must be at least the median shot. Every one of those is a plausible product rule and none is derived from data. A rubric with uncalibrated thresholds is a rubric that can be wrong in a confident voice.

Worse, the thresholds are *self-consistent with the planner*: the hook band's upper edge of 3.2 s sits just above the 3.0 s cap v2.12 imposed, so the planner now passes a test it helped define. That is circular, and it is the same class of defect as a fixture whose inputs are interchangeable.

**Proposed resolution.** Score a set of plans the owner considers good and bad — even ten, hand-labelled — and report the rubric's separation on that set. If it cannot separate them, the thresholds are wrong and the rubric is decoration.

## 6 — The rubric is not wired into the repair loop

**Severity: low.**

`rubric.score()` is a function nobody calls in production. §7.5's repair loop fixes violations the *schema* reports; it does not consult quality, so a plan that validates and scores badly is shipped.

**Proposed resolution.** A repair trigger on `verdict == "below bar"`, with the rubric's failing criterion naming what to change — a hook too long is a different repair from a total that misses its target.

## How this list is maintained

A finding enters when it is noticed and substantiated — a section number, an arithmetic error, or two rules that cannot both hold. It leaves when a version resolves it, and the resolution is named in that version's §0 table. It is never quietly dropped.

Finding 5 is the one to read twice: a rubric written to catch a planner's flaw, with a threshold the planner's own fix now satisfies, is a test that agrees with the code because the same person wrote both in the same hour.
